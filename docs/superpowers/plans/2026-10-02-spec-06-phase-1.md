# Spec 06 Phase 1 Implementation Plan (analytics capture)

> **For agentic workers:** use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Capture anonymous visitor analytics on public pages with PostHog, so data accumulates before the dashboard (Phase 5) exists (spec 06 §7.1).

**Architecture:**
- `instrumentation-client.ts` loads `posthog-js` on idle, and only when a project token is set and `shouldTrack()` allows it.
- All options live in the pure `lib/analytics/client-config.ts`.
- Events go through a same-origin `/rp/*` rewrite, built by the pure `lib/analytics/proxy.ts`.
- Named clicks are plain `data-ph-capture-attribute-*` attributes from `lib/analytics/attributes.ts`. `Button`, `TextLink` and `ApplyButton` accept them through a `track` prop.

**Spec:** `docs/specs/06-admin.md` §7.1 and §8 (Links, Footer rows).

## Global Constraints
- **Without the token, nothing loads:**
  - Without `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN`, no analytics code runs. Local dev and tests stay inert.
  - Public pages stay `○ Static`.
  - No `posthog-js` in the initial bundle: it's a dynamic import only.
- **Never tracked:**
  - `/admin` paths;
  - a browser with the `tac:internal` localStorage flag (set by `/admin` in Phase 2);
  - visitors with DNT or GPC enabled.
- **Storage:** localStorage persistence, no cookies, no session recording, no surveys, `person_profiles: "identified_only"`.
- **Click names:** `cta` is the action (a slug), `placement` is where it sits, and `target` is the specific item.

## Tasks
1. **`lib/analytics/attributes.ts`**
   - `trackAttrs(track?)` and `ctaFromLabel(label)`.
   - Tests: no attributes without a track; slugged labels.
2. **`lib/analytics/client-config.ts`**
   - `isAdminPath`, `shouldTrack(ctx)`, `readTrackContext(win)`, `uiHostFor(ingestHost)` and `posthogConfig(isInternal)` (`Partial<PostHogConfig>`, including `before_send`).
   - Tests: each exclusion rule; `before_send` drops `/admin` and internal events; config values.
3. **`lib/analytics/proxy.ts`** and `next.config.ts`
   - `posthogRewrites(ingestHost)` covers `/rp/static`, `/rp/array` and `/rp/*` for US and EU hosts.
   - Set `skipTrailingSlashRedirect: true`.
   - Tests: the rewrite list and its order.
4. **`instrumentation-client.ts`:** an idle-deferred dynamic import, gated on the token and `shouldTrack`.
5. **Track props**
   - `Button`, `TextLink` and `ApplyButton` (with a `placement` prop) spread `trackAttrs`.
   - Tag these call sites:
     - header Apply (desktop, compact, menu) and nav links;
     - hero, band and apply-page actions;
     - sponsor links, LinkedIn and Tracks lead links;
     - footer nav, Apply and socials.
   - Component tests assert the attributes.
6. **Canonicals and footer notice**
   - Add `alternates.canonical` to `/`, `/about`, `/membership`, `/team` and `/apply`, which `skipTrailingSlashRedirect` makes necessary.
   - Add a one-line analytics notice to the footer.
7. **Verify**
   - `pnpm typecheck && pnpm lint && pnpm test && pnpm build`: the route table is unchanged, and there's no `posthog` in the first-load chunks.
   - Browser: tracking attributes appear in the DOM; no `/rp` requests without a token.
8. **Provisioning (needs Jason's go-ahead):** `vercel link`, then `vercel integration add posthog`, then `vercel env pull`. After that, confirm events arrive in PostHog Live Events from local dev.
