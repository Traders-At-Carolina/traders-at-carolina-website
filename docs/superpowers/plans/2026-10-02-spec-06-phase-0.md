# Spec 06 Phase 0 Implementation Plan (refactor, no behaviour change)

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to run this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare the codebase for the admin dashboard without changing anything a visitor can see. Validators gain a non-throwing form, content types gain `ImageAsset`, and the public site moves into an `app/(site)` route group so `/admin` can have its own shell.

**Architecture:**

- `lib/validation.ts` holds one `assertNoProblems` helper.
- Each `lib/validate-*.ts` exports a pure `collect*Problems(): string[]`. Its existing `validate*` wrapper throws through the helper, with the same message as today.
- `ImageAsset` replaces `StaticImageData` in `content/types.ts`. Static imports still satisfy it.
- `components/SiteChrome.tsx` takes the skip link, header, `<main>` and footer out of `app/layout.tsx`. `app/(site)/layout.tsx` and `app/not-found.tsx` render it.

**Tech stack:** Next.js 16.3.8 (App Router, typed routes), React 19, TypeScript, Vitest 5 + Testing Library (jsdom).

**Spec:** `docs/specs/06-admin.md`, §5 (`ImageAsset`, validation), §8 (public-site changes) and §9 (Phase 0).

## Global Constraints

- **No behaviour change.**
  - Same URLs.
  - Same DOM order: skip link, header, main, footer as direct children of `<body>`.
  - Same validation error messages.
  - Every route still `○ (Static)` in `next build`.
- Validators keep running at module top level in each page. Moving them into async page functions is Phase 3+.
- No new dependencies.
- Spec 00 tokens only. No raw hex values.

Baseline before starting is `0cccfed`. `pnpm test` gives 30 files and 234 tests. `next build` gives 11 routes, all static:
`/`, `/_not-found`, `/about`, `/apple-icon.png`, `/apply`, `/icon.svg`, `/membership`, `/robots.txt`, `/sitemap.xml`, `/styleguide`, `/team`.

- [ ] **Step 3: Implement the helper and the split.**

  `lib/validation.ts`:
  ```ts
  /** Throws one error listing every content problem, so a single build run surfaces them all. */
  export function assertNoProblems(label: string, problems: string[]): void {
    if (problems.length > 0) throw new Error(`Invalid ${label}:\n- ${problems.join("\n- ")}`);
  }
  ```

  Apply the same mechanical change to each `lib/validate-*.ts`:
  1. Rename the body into `collect<X>Problems(...)`, keeping the `problems` array and every `push`.
  2. Replace the trailing `if (problems.length > 0) throw …` with `return problems;`.
  3. Re-add `validate<X>` as a one-line wrapper.

  Example, `lib/validate-home.ts`:
  ```ts
  import { assertNoProblems } from "@/lib/validation";

  /** Every content/home.ts problem (spec 01 §6); empty when valid. Admin saves show these as form errors (spec 06 §5). */
  export function collectHomeProblems(home: HomeContent): string[] {
    const problems: string[] = [];
    // …existing checks, unchanged…
    return problems;
  }

  /** Fails the build with every content/home.ts problem listed at once (spec 01 §6). */
  export function validateHome(home: HomeContent): void {
    assertNoProblems("content/home.ts", collectHomeProblems(home));
  }
  ```

  For `validate-team.ts`, the wrapper keeps the soft headshot warning after the assert:
  ```ts
  export function validateTeam(team: TeamContent, placements: Placement[]): void {
    assertNoProblems("team content", collectTeamProblems(team, placements));
    const soft = lowResHeadshots(team);
    if (soft.length > 0) {
      console.warn(`Team headshots below ${MIN_HEADSHOT_WIDTH}px wide will look soft on high-density screens: ${soft.join(", ")}`);
  ```
