# Spec 07 Footer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the footer the site's one closing section: a navy CTA zone, a Club / Join / Reach link grid, a bone-on-black placement strip and the legal row, and remove the per-page navy `CTABand` from every page.

**Architecture:** `SiteFooter` (server component, rendered once by `app/layout.tsx`) composes the existing `CTABand`, `DeadlineSwitch` and `PlacementWall`. A tiny client wrapper, `FooterZone`, hides the CTA zone on `/apply` and the strip on `/team` using `usePathname`. Page components stop rendering `CTABand`; a CSS rule keeps the extra padding above the navy zone. Nothing new is added to `content/`.

**Tech Stack:** Next.js 16.3.8 (App Router, static pages), React 19, Tailwind v4 tokens in `app/globals.css`, Vitest + Testing Library (jsdom), pnpm.

**Spec:** `docs/specs/07-footer.md` (amends specs 00–05; see its §7). Read it before starting.

## Global Constraints

- Tokens from spec 00 only. No new colors: bone `#ebeae4` text on black `#000000` and navy `#233265`; hairlines `border-rule-inverse`.
- **Exactly one navy band per page, and it is the footer's CTA zone.** `/apply` has none. No page component may render `CTABand`.
- `.on-dark` only recolors the focus ring (bone). It does **not** remap tokens (unlike `surface-graphite`), so on black use explicit classes: `text-bone`, `text-bone/70`, `border-rule-inverse`, `Eyebrow tone="inverse"`, `TextLink tone="inverse"`.
- Touch rows are at least 44px (`max-md:hit-target` on standalone links, `min-h-11` rows), as the footer does today.
- External links open in a new tab with `rel="noopener noreferrer"` (`Button` and `TextLink` do this when `external`).
- CTA copy and actions come from `homeApplyCopy()` in `lib/home.ts`; do not write new CTA copy.
- This Next version has breaking changes (AGENTS.md). `usePathname` is a Client Component hook; docs: `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/use-pathname.md`. The repo has no rewrites or proxy, so static prerender does not cause a hydration mismatch. If a proxy or rewrites are added later (spec 06), revisit `FooterZone`.
- Commands: `pnpm test` (vitest run), `pnpm typecheck`, `pnpm lint`, `pnpm build`. Run from the worktree root.
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` (second `-m`).

```tsx
"use client";

import { usePathname } from "next/navigation";
import type { ReactNode } from "react";

type FooterZoneProps = {
  /** Exact paths, e.g. "/apply", where this part of the footer is not rendered. */
  hideOn: string[];
  children: ReactNode;
};

const withoutTrailingSlash = (path: string) => (path.length > 1 ? path.replace(/\/+$/, "") : path);

/**
 * Hides part of the footer on specific routes (spec 07 §2). The footer is a server component in the root layout and
 * cannot read the route itself; its server-rendered children pass through here untouched.
 */
export function FooterZone({ hideOn, children }: FooterZoneProps) {
  const pathname = withoutTrailingSlash(usePathname());
  return hideOn.includes(pathname) ? null : <>{children}</>;
}
```
