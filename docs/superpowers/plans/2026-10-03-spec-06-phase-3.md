# Spec 06 Phase 3 Implementation Plan (editor framework + Photos)

> **For agentic workers:** use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Build the editing framework every later editor reuses, and ship Photos end to end. Home "Inside the club" and the Membership photo bands then read from Neon, so an admin's save is live within seconds (spec 06 rev 2 §3, §6.0, §6.6, §6.16).

**Spec:** `docs/specs/06-admin.md` (revision 2).

## Global Constraints
- **Public pages stay `○ Static`.** They read only through `unstable_cache` getters in `lib/data/public.ts`, tagged `photos`.
- **Every write goes through `lib/admin/action.ts`:**
  1. `requireAdmin`;
  2. zod parsing;
  3. the collection's rules;
  4. the database write;
  5. an audit entry with `before`/`after`;
  6. `updateTag`.
- **Undo** replays an entry's `before` through the same path. It is refused if a newer entry exists for the same item.
- **Slots** are one audited unit per page (entity `photo-slots`, id `home` | `membership`). Photo snapshots leave the slot columns out, so a content undo never fights a slot undo.
- **Slot rules:**
  - Home: 0, 2 or 3 photos (matches `collectHomeProblems`).
  - Membership: 0, 1 or 3 (the wide band, then the pair).
  - A slotted photo cannot be deleted.
- **Without `DATABASE_URL`:** only in non-production, the getters fall back to `content/*.ts`.

## Tasks
1. **Pure helpers, with tests**
   - `lib/admin/image-prep.ts`: `fitWithin`, `isHeic`, `uploadPathname`.
   - `lib/admin/photos.ts`: `slotProblem`, `photoSnapshot`.
   - `lib/admin/diff.ts`: `changedFields`.
   - `lib/admin/undo-plan.ts`: `planUndo`.
2. **`lib/data/public.ts`:** `getHomePhotos` and `getMembershipPhotos`. Home and Membership pages become async and validate inside.
3. **`lib/admin/action.ts`:** `adminAction`, `audited`, `ActionState`. Add `recordAudit` returning its id, plus `undoChange` with an entity registry.
4. **Components:**
   - `ImageUpload` (drag/drop, downscale, blur, `upload()` to `/api/admin/blob`);
   - `SaveToast` (Undo, View on site);
   - `useUnsavedChanges`;
   - grouped `AdminNav`.
5. **Photos screens:** `/admin/photos` (library, Home and Membership slot forms) and `/admin/photos/new` and `/admin/photos/[id]` (form with a ratio-cropped preview, plus delete).
6. **History** `/admin/history`: filters, a field diff and Undo. The Overview's recent changes get Undo.
7. **Verify:** lint, typecheck, tests and build (public routes still static). Then the dev server against the Neon dev branch: create a photo, slot it, check that Home updates, undo it, and check History.
