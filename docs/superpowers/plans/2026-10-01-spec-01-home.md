# Spec 01 Home Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to run this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Home page (`/`) per spec 01 using the spec 00 components. Content-dependent sections stay hidden until real data exists.

**Architecture:**
- `content/home.ts` holds typed content, and `lib/` holds pure, tested logic: date formatting, Apply copy, upcoming visibility, section numbering and validation.
- `components/home/*` are server components that take content as props, so they can be tested with fixture data.
- `app/page.tsx` wires in real content, validates it at build time and sets metadata.

**Tech Stack:** as in spec 00. Photos are static imports (`StaticImageData`), which give width, height and blur placeholders.

**Spec:** `docs/specs/01-home.md`. It depends on `00-vision-and-style.md` and `05-apply.md` §3.

## Global Constraints

- Spec 00 tokens only; no raw hex values or font stacks.
- No placeholder stats or stock photos ship. With no stats, "By the numbers" is hidden; with fewer than 2 photos, "Inside the club" is hidden.
- Section numbers (`§ 0N`) are always sequential over the sections that render.
- Dates are formatted from ISO values in America/New_York.
- The page has exactly one navy band and one `<h1>`.

## Decisions filling gaps in the spec

- "By the numbers" is omitted entirely when no stat has a value. The spec only covered single missing stats.
- `photos` must have 0 or 2–3 entries. Exactly 1 fails validation, since the spec requires 2–3 and 0 means hidden.
- "Upcoming" counts as visible through the end of the event's day, Eastern time.
- `stats.partnerFirms` stays an explicit optional field for now. Spec 02 adds the derivation from `about.partners`.

## Tasks

### Task 1: Pure logic (TDD)

- `lib/format.ts`:
  - `formatEventDateTime(d)` → "Thu, Oct 16 · 7:00 PM"
  - `formatMonthDay(d)` → "Jan 12"
- `lib/home.ts`:
  - `isUpcoming(isoDateTime, now)`
  - `homeApplyCopy(state)` → `{ hero: {label, href, external, arrow}, band: {title, label, href, external} }`, per spec 01 §5
  - `numberSections(keys: string[])` → `Record<key, n>`
- `lib/validate-home.ts`: `validateHome(home)`. Checks: exactly 3 pillars; 0 or 2–3 photos; non-empty `alt` and caption; `headlineEmphasis` is a substring of `headline`; `upcoming.date` parses. Lists every problem.
- Tests for all of the above.

### Task 2: Content type and file

- Add `HomeContent` to `content/types.ts`.
- `content/home.ts` uses the working copy from the spec, with stats empty, no photos and no upcoming event.

### Task 3: Section components and page

- `components/home/Hero.tsx`:
  - Display H1 with italic emphasis; eyebrow `§ 01`; subhead.
  - Apply button and a "How membership works →" link.
  - Random walk on graph paper: columns 8–12 on desktop, a 120px strip below the actions on mobile.
  - Height: min 560px / about 80vh / max 760px from `lg` up.
- `components/home/Pillars.tsx`: three hairline-divided columns, each with an `01`–`03` numeral, H3, body and link.
- `components/home/ByTheNumbers.tsx`: white section with a `StatRow`.
- `components/home/InsideTheClub.tsx`: photo layouts with and without the Upcoming card; figures with captions; slight desaturation.
- `components/home/HomePage.tsx`: composes the sections. Takes `{ home, recruiting, now }`, computes visibility and numbering, and renders a `CTABand` with the Apply copy.
- `app/page.tsx`: validates, sets metadata (an absolute title, with the subhead as description), renders `HomePage`.
- `next.config.ts`: `images.formats: ["image/avif", "image/webp"]`.
- **Tests:**
  - Hidden sections when data is empty.
  - Numbering stays sequential when stats are hidden but photos show.
  - Open and closed Apply states for both the hero and the band.
  - A past `upcoming` event gives the photo-only layout.
  - Exactly one `h1`.

### Task 4: Verify

- `typecheck`, `lint`, `test` and `build` all pass.
- Browser check at 375, 768, 1280 and 1440 widths: hero content above the fold, and the mobile strip.
- Keyboard pass.
- Lighthouse on mobile, plus a performance trace.
- Commit each task.
